教师考编信息雷达 V8｜最终部署版

这是在 V6 逻辑复核基础上完成的最终部署版。**请上传 V8，前面的 V4/V5/V6/V7 都不用再部署。**

## V8 这轮继续完善的内容

- **官方链接更明确**：列表与详情都可直接打开官方公告、报名入口、岗位表/附件；详情页增加“复制公告链接”。
- **地区快捷筛选**：增加“合肥全域 / 安徽全省 / 江苏巡考”，避免选“合肥”时漏掉蜀山、瑶海、包河等区县。
- **直接报名入口筛选**：可一键只看已经识别出官方报名系统的公告。
- **报名前核验清单**：详情页集中提示“官方原公告、初中语文证据、专业条件、教资、报名时间、岗位附件”是否已经提取。
- **个人备注**：每条公告可保存自己的报名/核验备注；备份与恢复个人标记时会一起保存，CSV 导出也包含备注。
- **附件识别更稳**：扩展名不在 URL 里的政府下载链接，会继续结合响应头和文件特征识别 PDF/Excel/Word；Excel 行结构也进一步保留。
- **匹配判断更保守**：当“研究生不限专业”和“本科阶段专业须对应”同时出现时，不再直接判为高度匹配，而是提醒重点核实。
- **无发布日期的 2027 届秋招日期修正**：若当前为 2026 年且页面明确是 2027 届校园招聘，正文只写“10月8日”时按 2026 年理解，不误排到 2027 年。
- **官网健康信息更完整**：增加最近成功时间、连续失败次数和单来源耗时，方便识别“网站真的没公告”还是“抓取异常”。
- **下载保护**：自动解析附件设置大小上限，避免异常大文件拖垮 GitHub Action。
- **历年趋势对比**：新增按地区/年份平铺的比较页，分别显示公告总招、初中语文招聘数、总报名、语文报名、竞争比、最低分、拟聘和已收录环节；没有官方数据就显示“—”。
- **招聘性质识别**：增加校招、统招、社招/公开招聘、人才引进/选聘等标签；无法可靠判断时保留“其他/待核”，不硬猜“单招”。
- **目标学科数字单独标记**：若官方材料明确写出初中语文招聘数、报名数或最低分，会和公告总人数分开显示，避免把整体数据冒充语文岗数据。

## 你的筛选画像

系统按以下条件做“初筛”，不把机器判断当作最终报考资格：

- 2027届应届硕士毕业生，预计 2027 年 6 月毕业
- 本科：小学教育
- 硕士：现代教育技术
- 已有：高中语文教师资格证
- 目标优先：初中语文
- 特别关注：研究生/硕士不限专业、专业不限、教育类可报、本科或硕士任一阶段满足即可、专业限制相对宽松

## V7/V8 前已完成的关键修复

1. **“2027届”不等于报名年份 2027**：例如 2026 年秋季发布的 2027 届校招，如果正文只写“10月8日”，现在优先按公告发布年份 2026 解析，不会误排到 2027 年。
2. **当前年份旧公告不再误放到近期可报**：已经截止的 2026 年春招会进入历年考情；无日期但明确属于当前/下一届的新公告才保留在近期池等待核实。
3. **政府下载链接的附件识别更稳**：支持 `downfile.jsp?filename=xxx.xlsx` 等“扩展名藏在查询参数”的常见政府网站写法。
4. **不再无意义下载 ZIP/RAR/旧 DOC**：这些附件仍保留官方链接，但不会浪费 Action 时间下载无法解析的大文件。
5. **HTML 岗位表按“整行”保留**：减少“初中语文”与“汉语言文学/专业不限”等条件被网页单元格拆散后造成误判。
6. **教资判断更谨慎**：若公告明确写“初中及以上语文教师资格证”，会识别你的高中语文教资为匹配；若写“学段、学科与岗位一致”，会标为“需核”，不擅自认定。
7. **本科专业对应限制单独预警**：出现“本科阶段专业须与招聘岗位对应”等字样时，不会因为你是硕士就误判为可报。
8. **普通教学新闻不再混入招聘库**：如“语文教学研讨”“研究生教育论坛”不会因为包含“语文/研究生”就被抓成招聘公告。
9. **官网导航优先级修正**：不会因为某网站域名里带 `jytyj` 就把所有新闻页面都当成招聘栏目；优先进入“教师招聘/招考/招录/人事信息”等页面。
10. **历史回溯改为可持续推进**：每日深度任务保存“未翻完的分页前沿”，第二天从那里继续，避免每天永远只翻前 10 多页，逐步向近 3—5 年扩展。
11. **历史数据不会一次抓太多把 Action 拖死**：快速任务和深度任务分别设定新增/刷新预算，历史数据分批补齐，并在页面显示“待回溯/待翻页”。
12. **新增报名入口抽取**：除官方公告外，能识别到“报名入口/报名网址/考试服务平台”的会直接显示。
13. **时间信息补齐**：列表直接显示报名开始、报名截止倒计时、笔试日期、面试日期；当前列表还可导出 `.ics` 日历。
14. **即将截止真正置顶**：有明确未来截止日期的岗位按剩余天数从近到远排序。
15. **网页“正常打开”但抓不到公告不再算正常**：会标成“可访问但未发现候选”，用于识别 JS 动态加载、反爬或入口不够精准的情况。
16. **首次部署不会再假装巡检正常**：45 个来源会先显示“待首次巡检”；只有 Action 真跑过后才给健康结论。
17. **超时/停更预警**：如果距离最近一次自动巡检超过约 3.5 小时，首页会明确提示检查 GitHub Actions，而不是让你误以为“今天没公告”。
18. **两套任务不会相互取消**：小时快速巡检和每日深度回溯共用并发锁，避免一个任务把另一个正在运行的任务取消。
19. **增加离线回归测试**：每次 Action 正式抓取前都会运行 `self_check.py` 和 `test_logic.py`，先检查配置、Python、前端 JS 和关键解析规则。

## 两层更新机制

### 1. 每小时快速巡检

工作流：`Update teacher exam radar`

作用：优先查看各官网近期页面，及时发现新公告、报名、笔试、资格复审、面试、拟聘、递补等变化。

### 2. 每日深度回溯

工作流：`Deep backfill teacher exam radar`

作用：每天继续翻历史分页，逐渐补足近 3—5 年数据。为了不因一次抓取几千个页面而超时或被政府网站封禁，历史库是**持续补全**的，不是假装第一次部署就已经完整。

页面会显示：

- 待回溯：已经发现但本轮尚未解析的公告数；
- 待翻页：下一次深度任务还要继续翻的历史栏目页面数。

只有这两个数字逐步降低，历史库才是在真正趋于完整。

## 第一次部署（只需要做一次）

1. GitHub 新建一个仓库；已有旧版仓库可以直接用 V8 文件覆盖。
2. 解压 ZIP，把**全部文件和隐藏的 `.github` 文件夹**上传到仓库根目录。
3. GitHub → `Settings` → `Pages`：
   - Source：`Deploy from a branch`
   - Branch：你的默认分支（通常是 `main`）
   - Folder：`/docs`
4. GitHub → `Actions`：
   - 先手动运行一次 **Update teacher exam radar**；
   - 再手动运行一次 **Deep backfill teacher exam radar**。
5. 等 Pages 网址生成后打开网页，先看 **“官网覆盖状态”**，不要只看公告数量。

### 如果 Action 提示没有写入权限

到：`Settings` → `Actions` → `General` → `Workflow permissions`，选择 **Read and write permissions** 后保存，再运行。

## 首次运行后应该先检查什么

优先看“官网覆盖状态”：

- **正常**：页面可访问，并识别到招聘相关候选；
- **可访问但未发现候选**：网站能打开，但可能是 JS 动态页、入口太宽或暂时确实没有相关标题，需要后续适配；
- **部分失败**：部分页面抓到，部分页面失败；
- **抓取失败**：这一来源本轮不能依赖；
- **待回溯 / 待翻页**：历史数据还在分批补。

因此“某地区没有记录”只有在来源状态健康的前提下才有参考意义。

## 对“竞争比”的处理原则

系统不会把整个地区的报名人数冒充“初中语文竞争比”。

如果同一官方页面抽取到报名人数与招聘计划数，页面只显示 **“整体报名/计划比”**，它不是初中语文岗位竞争比。只有官方材料明确给出岗位/学科口径后，才应把它用于具体岗位判断。最低进面分同样只抓明确写出的数字，不从名单自行猜测。

## 仍然存在的外部限制

这些不是继续改几行代码就能完全消除：

1. **验证码 / 登录 / 强反爬 / 403**：自动任务可能无法进入；覆盖状态会显示。
2. **纯 JS 动态页面**：普通 HTTP 抓取可能只有空壳；会尽量标成“可访问但未发现候选”，而不是“正常”。
3. **扫描版 PDF**：当前不启用 OCR。没有文字层时只保留附件链接并标“未解析”，避免误识别。
4. **老式 `.doc` / `.wps` / 压缩包**：保留链接但不自动解析。
5. **高校就业网/微信公众号的异地校招信息**：不可能仅靠固定政府官网 100% 覆盖，因此仍建议保留 ChatGPT 每日检索作为第二条发现通道；发现新官方栏目后再纳入固定巡检。
6. **机器匹配不是资格审查**：尤其是“相近专业”“本科/研究生任一阶段”“学段学科一致”等，最终必须回到官方岗位表或咨询招聘单位。

## 隐私提醒

如果使用**公开 GitHub 仓库**，仓库代码和 `docs/data/profile.json` 中的报考画像（小学教育、现代教育技术、高中语文教资、2027届等）也是公开可见的；当前文件里**没有姓名、手机号、身份证号等个人身份信息**。如果你不希望这些报考画像公开，可以在部署前再改成“隐私模式”。

## 文件说明

- `sources.json`：固定官网白名单；
- `docs/index.html`：网页；
- `docs/data/items.json`：公告/历史数据；
- `docs/data/source_status.json`：官网巡检健康状态；
- `docs/data/chains.json`：招聘链条；
- `docs/data/profile.json`：你的筛选画像；
- `scripts/update.py`：抓取、附件解析、匹配、历史回溯；
- `scripts/self_check.py`：配置和前端静态检查；
- `scripts/test_logic.py`：关键规则回归测试；
- `.github/workflows/update.yml`：每小时快速巡检；
- `.github/workflows/deep_update.yml`：每日深度回溯。
