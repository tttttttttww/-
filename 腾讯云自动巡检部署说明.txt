# 教师考编信息雷达｜腾讯云原生自动巡检版

这一版已经不再依赖 GitHub Actions 才能更新数据。

## 架构

- EdgeOne Makers：继续托管现有网页。
- Makers Cloud Functions（Python）：直接运行原来的官网抓取、PDF/Excel/Word 解析逻辑。
- Makers Blob：持久化 `items / status / chains / runtime`，网站刷新即可读取最新数据。
- `edgeone.json schedules`：腾讯云原生定时触发，不需要服务器、不需要电脑开着。
- GitHub Actions 文件仍保留，仅作为备用，不影响腾讯云原生自动巡检。

## 自动巡检频率

EdgeOne 的单个 schedule 当前按官方文档要求至少间隔一天，因此本项目采用“多个每日分批任务错峰运行”的方式：
- 87 个固定官方入口分成 18 批，在北京时间 05:10—22:10 逐批扫描一遍；
- 每天 02:30 自动做一小批深度历史回溯；
- 打开网页超过 4 小时未更新时，会自动尝试触发一批本地重点巡检；
- 页面顶部可点击“立即巡检合肥”，连续扫描合肥全域前 3 批。

## 上传后不需要配置数据库

Makers Blob 使用 `getStore("teacher-exam-radar")` 自动创建存储空间，第一次成功巡检后即可在 Blob 中看到数据。

## 可选安全设置

为了防止公开仓库中的内部写接口被误调用，可在 EdgeOne 项目环境变量里设置：
`RADAR_INTERNAL_TOKEN = 任意一串你自己知道的长随机字符串`

不设置也能运行；程序会使用内置默认值。个人自用可以先不设置，等跑通后再加。

## 部署后怎么确认成功

1. 覆盖上传本包全部文件到原 GitHub 仓库 main 分支。
2. EdgeOne 会自动重新部署。
3. 打开网站，顶部应看到“腾讯云自动巡检”和“立即巡检合肥”。
4. 点击一次“立即巡检合肥”。
5. 等待第一批返回后，页面“最近巡检”应出现真实时间；“官网覆盖状态”里会出现真实抓取结果。
6. 以后即使 GitHub Actions 不工作，腾讯云原生 schedule 仍会继续执行。

## 说明

Cloud Functions 单次最长 120 秒，所以平台故意分批扫描，而不是一次请求 87 个网站。这样更稳，也更不容易被政府网站限流。
